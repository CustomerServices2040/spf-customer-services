# Busola Design System 3.0

مرجع التنفيذ الحالي — لقطة مصدر بتاريخ `2026-11-13T15:29:11.697252+00:00`، على فرع `design/busola-system-3-review`، مقارنة بأساس 2.0 `eea4843e43cde49c8a0810101e48609ee4a62dab`.

## النطاق والبنية

يستخدم النظام طبقة CSS واحدة باسم `busola` فوق ملفات التنسيق القديمة. استخدام `!important` داخل هذه الطبقة مقصود للتغلب على التصريحات القديمة غير الموجودة داخل طبقة؛ ليس ترخيصاً لإضافة تجاوزات متفرقة خارجها. الرموز الدلالية، ثم سياق السطح، ثم استثناء المكوّن المحدد هي ترتيب التخصيص المفضل.

| العلامة | العقد |
|---|---|
| `data-busola-theme` | اختيار أحد `original / green / navy / burgundy` عبر المحرك الموجود. |
| `data-bs-type` | الخطوط والأحجام وتعديلات التخطيط المشتركة للأنماط الأربعة، بما فيها Original. |
| `data-bs-active` | ألوان وأسـطح الأنماط الثلاثة الجديدة؛ تُزال عند اختيار Original. |
| `data-bs-component` | العائلة البصرية المشتقة من نوع المكوّن الموجود. |
| `data-bs-surface` | `dark / light / subtle`؛ يحدد سياق اللون، ولا يغير البيانات. |
| `data-bs-kpi` | `hero / primary / secondary`؛ يختار رتبة الرقم. |
| `data-bs-executive` أو `.presentation-fullscreen` | تفعيل أحجام العرض التنفيذي عند عرض نافذة لا يقل عن 1800px. |
| `data-appearance-motion` | إعداد الحركة الموجود: `standard / calm / lively / off`. |

تُحقن القواعد أيضاً في Shadow DOM الخاص بالتواصل والإعلام، وتوضع علامات النوع والنمط على `.comm-shell`. تستخدم صفحات iframe استوديو المظهر الموجود وتستقبل تفضيلات الأصل عبر رسائل من المصدر نفسه. لم يُنشأ منتقي ألوان ثانٍ أو مخزن بيانات تشغيل جديد.

**Original في 3.0:** يخضع للنظام الطباعي وتعديلات التخطيط المشتركة. لا تُفرض عليه لوحة 60–30–10 الجديدة. تبقى ألوانه الأصلية في ملفاتها؛ التخصيص اللوني الشخصي، عند طلبه داخل Studio، يمر عبر adapter معزول داخل المحرك نفسه ويُستعاد قبل تبديل النمط. وجود المحددات بهذا الشكل لا يغني عن مقارنة الألوان فعلياً.

هذه قيم أساس قبل تخصيص المستخدم وملاءمة الرقم. لا يعني عرض شاشة 1920px وحده تفعيل العرض التنفيذي؛ يلزم أيضاً أحد المحددين المذكورين. ولا يثبت الحجم بالبكسل وحده قابلية القراءة من مسافة مشاهدة محددة.

لا يدّعي النظام أن كل عنصر نصي أصبح بالقيم نفسها: توجد استثناءات واضحة مثل `.page-heading h1` بحجم 18–26px، و eyebrow الشريط 12px ثم 11px على الهاتف، وتسمية `.cc-rate-ring` 14px، وتسمية `.target-ring` تتبع النص المساند 14px مع تخصيص الحجم، وعناوين وأزرار الاستوديو بأحجام خاصة. حقول الإدخال في الأنماط الأربعة تتبع حجم النص الأساسي 16px مضروباً في تخصيص الحجم. كذلك تبقى عناصر متخصصة وقواعد قديمة وأجزاء من الرسوم والصور تحتاج تحققاً مستقلاً.

## الأرقام والملاءمة

الحجم الفعلي للرقم الدلالي:

```css
font-size: calc(var(--bs-kpi-size) * var(--bs-user-numbers,1) * var(--bs-fit,1));
font-variant-numeric: tabular-nums;
white-space: nowrap;
transition-property: color;
```

تُختار الرتبة بواسطة قوائم محددات في `themes.js`، وليس بتغيير نص الرقم. الفئة `hero` لها أولوية عند تطابق أكثر من قائمة. يقبل التعرف النص الرقمي المباشر والرموز الرقمية المدعومة، واللاحقتين «ألف» و«مليون» حيث توجد في المصدر. الوحدات التابعة داخل span/small/em تأخذ 0.38em؛ لا يُختصر النص أو يُعاد حساب قيمته.

الدالة `fit()` تجمع الأرقام الظاهرة، تعيد تعيين عواملها، ثم تنفذ حتى ثلاث دورات قياس/تطبيق بعد إعادة توزيع الأشقاء. عامل التصغير لا ينخفض عن 0.35. قصر انتقال KPI على اللون يمنع انتقال `font-size` من جعل القياس يرى حجماً وسيطاً. هذه آلية احتواء عرض، وليست دليلاً على سلامة الارتفاع أو الفراغ الداخلي للحلقات أو عدم تقاطع الأشقاء.

## الاستجابة والتخطيط

- `.content-wrap` حاوية `busola-content`: عند≤1050px تتغير الميزانية إلى عمودين والخريطة الخارجية إلى عمود؛ عند≤650px تتكدس الميزانية وقيمها وحاوية المحافظة الداخلية.
- `.workload-metrics` و`.workload-metrics.compact` و`.contact-kpi-grid` تستخدم `repeat(auto-fit,minmax(min(calc(280px * var(--bs-user-numbers,1)),100%),1fr))`؛ تتسع المساحة المطلوبة مع تكبير الأرقام، وتبقى بطاقة رضا المتعامل على كامل العرض. قاعدة الهاتف تبقي شبكة الاتصال عموداً واحداً.
- `.hero-metrics` تستخدم auto-fit بحد 260px، ثم عموداً واحداً على الشاشات الصغيرة. الهيرو الرئيسي يتكدس عند≤600px.
- بطاقات الأداء والقنوات المحددة تُرتّب رأسياً، وتترك ارتفاعها للمحتوى. `.cc-rate-ring` حلقة 220px مع رقم وتسمية في تدفق عمودي؛ الحلقة الرئيسية 220px، و 180px على الهاتف، و 280px في العرض التنفيذي الكبير.
- داخل `.filters`، تقبل labels الانكماش بـ`min-width:0`، وتلتزم input/select بعرض 100% وحد أدنى 0 وحد أقصى 100%؛ هذا يعالج عرض المحتوى الذاتي في مرشحات التقارير على الهاتف. لا يُعد وجود القاعدة وحده قبولاً بصرياً؛ نتائج إعادة الفحص الموجهة وحدودها في تقرير QA.
- لا تغيّر هذه القواعد جميع الشبكات القديمة إلى شكل واحد. الجداول والخرائط والصفحات التابعة تحتاج فحص محتواها الفعلي.

مقاسات القبول المطلوبة: 390 / 768 / 1024 / 1440 / 1920px، مع حالة Studio المفتوح، واختيار أقصى حجم نص ورقم وحشو، والعرض التنفيذي مستقلاً.

## Motion Tokens والتنفيذ الفعلي

| الرمز | القيمة المعلنة |
|---|---|
| `--bs-motion-press` | 180ms |
| `--bs-motion-menu` | 250ms |
| `--bs-motion-reveal` | 420ms |
| `--bs-motion-data` | 1100ms |
| `--bs-ease` | `cubic-bezier(.2,.7,.2,1)` |

الانتقالات الأساسية للأزرار والحقول تستخدم رمز الضغط. بقية الرموز مرجع مركزي معلن، لكن الملفات القديمة لا تستخدمها كلها بعد: `motion-system.css` ما زال يحتوي ظهوراً0.9s، وأعمدة 1.4s، وحلقات 1/1.25s، ومسارات 1.7s. محرك الأرقام JavaScript القائم يستخدم 1100ms للأنماط ذات `data-bs-active`، ويحتفظ بمعادلته القديمة حتى 2200ms في Original، مع معاملات calm/lively. لذلك لا يُدّعى توحيد جميع الأزمنة فعلياً بمجرد تعريف الرموز.

Studio يتيح standard/calm/lively/off، ويكتب إعداد الحركة إلى العلامة الموجودة. إيقاف الحركة أو تفضيل النظام لتقليلها له الأولوية. تعديل `motion-system.css` في 3.0 يكشف المحتوى فوراً عند off ويعيد opacity/transform/stroke إلى حالة مرئية؛ وتحفظ دبوس الخريطة إزاحة `translate(-50%,-50%)` حتى لا يتحرك من إحداثياته. هذا تعديل CSS؛ منطق الحركة JavaScript وبيانات الرسوم لم يتغيرا عن أساس 2.0.

## Studio والتخصيص الشخصي

التخزين محلي بالمفتاح `busola.appearance.v1`، مع إعدادات مستقلة لكل نمط. لا تُكتب هذه القيم إلى بيانات التشغيل. القيم الأساسية ثابتة في النظام، وتطبق التفضيلات عبر رموز `--bs-user-*` أو تجاوزات دلالية على العنصر الجذري.

| الإعداد | الافتراضي / النطاق |
|---|---|
| الخط | `original` يعني الخط الموحد Noto؛ بديل Plex أو Noto الصريح. |
| النص `scale` | 1؛ من 0.9 إلى 1.3 |
| الأرقام `numbers` | 1؛ من 0.85 إلى 1.3 |
| الاستدارة | 18؛ من 0 إلى 28px |
| الظل | 1؛ من 0 إلى 2 |
| الحشو | قيمة تحكم 20؛ من 12 إلى 28px؛ لا يطبق تجاوزها حتى تفعيل تخصيص البطاقات. |
| الحد | solid / dashed / none |
| تخصيص البطاقات | `cards:false` أساساً |
| الحركة | standard أساساً |
| الألوان | قاموس فارغ؛ HEX من ست خانات عند التخصيص. |

يرتبط تكبير النص بـ`--bs-user-scale`، والأرقام بـ`--bs-user-numbers`، والخط بـ`--bs-user-font`. خيارات البطاقات تكتب `--bs-user-radius/padding/shadow/border`، ولون البطاقة `--bs-user-card`. تجاوز لون heading يستخدم `--bs-user-heading` على الداكن؛ سياق القراءة الفاتح يحافظ على لون حبره الدلالي.

الحفظ يثبت المسودة في المتصفح بعد فحص القيم والتباين. إعادة ضبط النمط أو العودة إلى Original تحدث المعاينة؛ حفظ التفضيلات هو إجراء التثبيت المحلي. لا يعني زر الرجوع إلغاء التحديث الطباعي 3.0 أو الرجوع إلى ملفات إصدار 2.0.

الهدف WCAG AA حيث ينطبق: 4.5:1 للنص العادي و 3:1 للنص الكبير، مع تركيز مرئي 3px وفاصل 3px، وتسميات وأزرار موجودة محفوظة. فحص Studio يفرق النص الكبير وفق 24px، أو 18.66px مع وزن≥700، ويمنع حفظ تخصيصات ألوان لا تجتاز فحصه. بعض فحوص الأدوار داخل Studio أكثر تحفظاً وتستخدم 4.5:1.

الأزرار و summary في الأنماط الجديدة لها حد ارتفاع 44px؛ الحالة المعطلة opacity0.55. لا تكفي هذه القواعد وحدها لإثبات مساحة اللمس لكل عنصر على Original أو جميع الرسوم. حالات النجاح/التحذير/الخطر لها أزواج مستقلة: `#D7F3E1/#254C39`، `#FCE7BD/#59411D`، `#FFE1DD/#6D302F`، مع بقاء المحتوى الدلالي للحالة.

في محور الملتقى المحدد، يضبط `[data-bs-active] .future-axis[aria-selected=true]` اللون المساند للسياق إلى `--bs-accent` والحد إلى `--bs-accent-ink`، لمنع بقاء الرقم بلون منخفض التباين بعد تغيير خلفية الحالة النشطة. النطاق هو الأنماط الجديدة؛ لا يغير لوحة Original.

لا يمثل فحص CSS أو فحص التباين المحلي شهادة WCAG كاملة. يجب فحص التدرجات والشفافية والصور و pseudo والعناصر التفاعلية وترتيب التركيز ولوحة المفاتيح وقارئ الشاشة فعلياً. التسمية أو رقم داخل صورة لا يصبح نصاً متاحاً بتغيير الخط الخارجي.
