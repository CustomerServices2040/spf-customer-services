## نقطتان تقنيتان مؤثرتان

**الصفحات المحمية:** سكربت الحماية الأصلي يحفظ snapshot من `document.documentElement.outerHTML` عند تنفيذه، ثم يعيد كتابة الوثيقة بعد فك التشفير المخوّل. يجب إدراج CSS الجديد ومرجع `experience.js` بصيغة `defer` داخل `head` قبل الوصول لهذا السكربت. إضافة السكربت البصري بعده في نهاية `body` تجعل المرجع غائباً عن snapshot؛ وقد يختفي المحوّل بعد فتح التبويبات. الحل هو موضع الحقن في البناء فقط، دون تغيير آلية الحماية.

**الغرف الحية:** `forum/config.js` يختار الخدمة الخارجية عندما يكون المضيف `customerservices2040.github.io`؛ في المضيف الخاص يصبح `FORUM_API_BASE` فارغاً، فتتجه الطلبات إلى `/api/rooms` على استضافة المعاينة الثابتة. هذه نقطة تحقق غير مكتملة، وليست ملفاً يمكن تعويضه دون تغيير مصدر البيانات. لا ننقل الجلسات أو نرسل مشاركات حقيقية لإثبات عمل التصميم.

## ما يثبته المدقق وما لا يثبته

تم توسيع `check_integrity.py` لفحص جميع HTML تحت `dist/`، وروابط التنزيل المحلية وposter وmeta refresh، وملفات CSS و`@import` و`url()` داخل CSS والأنماط المضمنة. لا ينفذ JavaScript، ولا يفك التشفير، ولا يجري اتصالات للخدمات البعيدة. لذلك لا يُستخدم بديلاً عن اختبار التنقل والخرائط والنوافذ والاستيراد في المتصفح.

يستدعي المدقق وحدة Node محلية لعكس **تحويل نصي محدد** لحركة تقرير الداخلية، وإعادة تطبيقه والتحقق من SHA-256. هذه العملية لا تشغّل سلوك التقرير في المتصفح أو إجراءاته، ولا تتجاهل شيفرته inline. يثبت الاسترجاع بعد نزع إضافات العرض المعروفة تطابق الملف الأصلي بالبايت، ويُفشل التدقيق عند اختلاف الحمولات أو نقاط التحويل أو ملف التدقيق.
